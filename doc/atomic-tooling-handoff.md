# CYRVIS 原子工具开发交接

> 更新时间：2026-11-19
>
> 用途：记录当前工具层实现、后续缺口和职责边界，供开发中断后继续推进。

## 1. 当前状态

- 注册工具共计 `88` 个，其中 `9` 个来自动态系统状态，另有 `6` 个工作流工具和 `1` 个多模态意图工具。
- 实时模型默认最多看到 `24` 个本地工具。
- 完整能力保存在 `CapabilityCatalog`，隐藏工具通过
  `capability.search / describe / invoke` 按需发现。
- 第一批新增了 `18` 个本地原子基础工具。
- `ToolRegistry` 统一负责参数准备、路径策略、风险检查、直接执行和审计。
- 当前工具层不负责复杂任务路由，Router 可以为后续独立开发模块。

第一批工具说明见
[atomic-foundation-tools.md](./atomic-foundation-tools.md)。

## 2. 已落地的设计原则

- 工具保持原子化，只完成一个明确动作。
- 工具按“观察、执行、等待、验证”分类，便于后续工作流组合。
- 完整目录与模型可见面分离，避免工具数量和 schema 占满上下文。
- 常用低风险工具可常驻；低频、重资源或高风险能力默认按需激活。
- 用户明确请求的进程执行、结束进程、电源操作和私有网络访问直接执行。
- 外部账号型服务应通过 Provider manifest 接入，不硬编码到核心工具矩阵。
- GUI 和未来 Codex 应作为执行器接入，而不是把所有内部动作提升为顶层工具。

| 分类           | 工具                                                                |

## 4. 后续仍缺的工具包

### 4.1 浏览器完整能力

当前有页面抓取、截图、OCR 和坐标级 UI 操作，但缺少完整浏览器会话工具：

- 标签页列表、打开、关闭和切换。
- 当前页面 URL、标题和 DOM/可访问性树。
- 页面文本、表格和链接提取。
- 元素查找、聚焦、点击、输入和选择。
- 表单填写、文件上传和下载管理。
- 页面加载、网络空闲和元素显示等待。
- 登录会话、Cookie、书签和历史的受控访问。

建议新增独立 `browser.*` 工具组，优先通过浏览器调试协议或现有 Browser
Operator 实现，不使用坐标点击模拟常规网页操作。

### 4.2 文档与数据

- 已支持纯文本、DOCX、XLSX、PPTX 基础文本提取；扫描 PDF 仍需 OCR。
- 尚缺 PDF 页面/表格/附件、Office 样式编辑、公式写入和复杂生成。
- 文档格式转换和模板填充。
- Excel 单元格、工作表和公式操作。
- 图片 OCR、文档截图和表格结构化提取。

### 4.3 个人数据与通信 Provider

这些能力依赖账号和权限，建议通过 Provider manifest 接入：

- 日历查询、创建、修改和删除。
- 待办、提醒和日程。
- 联系人查询。
- 邮件搜索、读取、草拟、附件和发送。
- SMS、微信、Teams、Slack 等消息能力。
- 云盘浏览、上传、下载和分享。

所有发送、删除、支付和凭据修改操作经过统一参数和路径检查；明确请求不再二次确认。

### 4.4 记忆与任务上下文

- 记忆搜索、写入、更新和删除。
- 用户偏好、常用路径、常用应用和实体。
- 最近文件、最近窗口、最近动作和任务结果。
- 指代解析所需的当前焦点、选中内容和活动上下文。

### 4.5 通知、调度与主动性

- 已支持单次本地通知、一次性计时器和取消/列表。
- 尚缺免打扰控制、重复提醒、持久化恢复和跨重启调度。
- 日程触发器和任务完成通知。
- 主动提醒的优先级、冷却和用户反馈。

### 4.6 系统与媒体

- Wi-Fi、蓝牙、VPN、代理和网络诊断。
- 音视频播放列表和媒体库。
- 截图增强、录屏、图片和音视频转换。
- 默认音频设备、显示器、启动项和服务管理。

### 4.7 文件高级能力

- 文件/目录监听和变化事件。
- 已支持 ZIP 创建和解压；尚缺更多归档格式、加密和分卷。
- 回收站枚举与恢复。
- 文件版本、检查点和回滚。
- 权限、属性和批量事务。

### 4.8 执行器封装

- 将现有 UI-TARS GUI Agent 封装为统一的 GUI Executor。
- 新增 Codex Executor：启动、状态、取消、隔离工作区、变更和验证结果。
- 为执行器统一任务状态、日志、超时、取消和确认协议。

## 5. Router / 工作流层需要补齐的逻辑

以下内容不建议继续塞进原子工具：

- 上下文与指代解析，例如“这个文件”“刚才那个窗口”“左边第二个链接”。
- 多步骤任务规划和 DAG 编排。
- 条件分支、循环、并发、依赖和超时。
- 关键步骤后的状态验证、局部重试和失败恢复。
- 文件操作事务、检查点、撤销和回收站恢复。
- 多任务队列以及 GUI、Codex、定时任务的统一生命周期。
- 显式指令直接执行，仅对缺失参数追问。
- 工具结果的统一归一化、用户反馈和下一步建议。
- 主动提醒的触发策略、冷却和免打扰。

## 6. 建议职责边界

| 层          | 负责内容                                 |
| ----------- | ---------------------------------------- |
| 原子工具层  | 观察、执行、等待、验证和领域单项操作     |
| Provider 层 | 日历、邮件、IM、云盘等外部账号服务       |
| 工作流层    | DAG、分支、并发、事务、重试和恢复        |
| Router 层   | 意图、上下文、候选能力、执行器选择和澄清 |
| GUI / Codex | 承担需要内部循环的复杂子任务             |

## 7. 推荐开发顺序

1. 建立浏览器工具组和页面状态验证。
2. 增加记忆、最近动作和当前上下文工具。
3. 封装统一 GUI Executor 和 Codex Executor。
4. 建立工作流 DAG 协议并接入 `condition.*`、`fs.hash`、`process.inspect`。
5. 增加通知、计时器和日程 Provider。
6. 增加文档、邮件、IM 和云盘 Provider。
7. 增加事务、回滚和多任务队列。

## 8. 断点续开发检查清单

- 先阅读本文和 [atomic-foundation-tools.md](./atomic-foundation-tools.md)。
- 新能力优先实现为 `ToolDefinition`，并接入 `ToolRegistry`。
- 为路径参数填写 `pathArgs`，并在 `prepare` 中校验必要参数。
- 设置合理的 `providerId / tier / activation / priority / tags / permissions`。
- 默认不要扩大模型的常驻工具面；低频能力按需发现。
- 为高风险和可恢复操作补充结构化错误、验证方法和安全约束。
- 更新 `doc/fast-tool-matrix.md` 中的工具数量和分类。
- 运行类型检查、CYRVIS 测试、ESLint 和生产构建。

## 9. 当前已知限制

- `screen.ocr` 和 `ui.inspect` 当前依赖 Windows 原生能力。
- `web.fetch` 和 `web.download` 对私有网络目标直接执行；重定向后的地址仍需进一步加固。
- `web.download` 超过上限时拒绝写入，不提供断点续传。
- `screen.capture` 当前输出到系统临时目录，尚无自动清理策略。
- `ui.action` 使用绝对坐标，调用前应先用 `ui.inspect` 获取控件位置。
- `process.run/start/stop` 和 `system.power` 按明确用户指令直接执行。
- GUI 内部的敏感动作同样遵循直接执行策略。
- Controller 当前仍以单一 GUI 任务为主，尚未支持多执行器任务队列。
