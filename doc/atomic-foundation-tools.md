# CYRVIS 原子基础工具

> 状态：2026-11-19 第一批本地基础工具已接入。
>
> 定位：为后续工作流编排、GUI 委派和 Codex 委派提供稳定、可组合、可验证的
> 单项执行能力。工具层不负责复杂任务路由。
>
> 本文档记录第一批新增工具的分类、功能，以及为什么需要把这些能力写入项目。

## 1. 设计边界

每个原子工具只完成一个明确动作，并返回结构化结果。组合、重试、分支、确认和
跨工具流程由上层任务 router 或工作流执行器负责。

工具应包含：

- 明确的输入 schema 和输出数据。
- 风险等级、权限、暴露层级和激活方式。
- 路径、网络或系统边界检查。
- 可独立验证的执行结果。
- 失败时可供上层恢复的结构化错误。

## 2. 第一批新增工具

### 观察与界面

| 工具             | 功能                                                        | 为什么写入项目                                                                                      | 默认暴露 |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------- |
| `screen.capture` | 截取当前屏幕或指定区域，保存为 PNG                          | 给工作流提供最基础的视觉观察能力，使系统能够保存现场、再次分析并验证动作后的界面变化。              | 按需激活 |
| `screen.ocr`     | 使用 Windows 原生 OCR 识别截图或指定图片                    | 很多应用没有 API 或辅助功能树，OCR 是读取这些界面文字的通用兜底，避免所有视觉任务都交给 GUI Agent。 | 按需激活 |
| `ui.inspect`     | 通过 UI Automation 读取前台窗口、控件、边界、焦点和选中文本 | 让后续工作流能定位控件、理解当前焦点和选中内容，并用坐标完成可验证的原子点击或输入。                | 按需激活 |
| `ui.action`      | 执行点击、双击、右键、移动、输入、快捷键、滚动和拖拽        | 把 GUI 行为拆成可重复调用的单步动作，使复杂任务可以选择整段 GUI 委派，也可以自行组装小动作序列。    | 按需激活 |

### 等待与验证

| 工具              | 功能                         | 为什么写入项目                                                                             | 默认暴露 |
| ----------------- | ---------------------------- | ------------------------------------------------------------------------------------------ | -------- |
| `condition.check` | 检查文件、进程或窗口条件     | 提供独立的“断言”原子能力，让工作流可以证明前置条件或执行结果，而不是依赖工具口头声称成功。 | 常驻     |
| `condition.wait`  | 等待文件、进程或窗口条件成立 | 下载、安装、启动应用和页面加载都需要时间同步；没有等待能力，复杂工作流只能依靠固定 sleep。 | 按需激活 |

支持的条件：

- `path_exists`
- `path_missing`
- `path_is_file`
- `path_is_directory`
- `process_running`
- `process_missing`
- `window_exists`
- `window_missing`

### 受控进程执行

| 工具              | 功能                                                    | 为什么写入项目                                                                                      | 默认暴露           |
| ----------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------ |
| `process.run`     | 使用 executable + args 执行程序并等待结果，不经过 shell | 补齐没有原生封装的外部命令工具，同时避免 shell 字符串注入；工作流可以得到退出码、stdout 和 stderr。 | 按需激活，直接执行 |
| `process.start`   | 启动分离的后台程序并返回 PID                            | 支持启动长耗时任务、服务或独立代理，并让上层工作流继续执行其他节点，而不是一直被阻塞。              | 按需激活，直接执行 |
| `process.stop`    | 按 PID 结束进程                                         | 提供资源和任务生命周期控制，使取消、超时清理和卡死恢复能够成为工作流的一部分。                      | 按需激活，直接执行 |
| `process.inspect` | 检查 PID 是否运行及进程信息                             | 为启动、停止和安装任务提供可验证的进程状态，避免只根据启动命令是否返回判断任务成功。                | 按需激活           |

### 网页读取

| 工具           | 功能                                                      | 为什么写入项目                                                                           | 默认暴露 |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------- |
| `web.fetch`    | HTTP/HTTPS GET，返回状态、类型和有大小上限的文本或 base64 | 让工作流可以直接读取网页或 API 数据，不必每次都打开浏览器、截图或用 GUI 提取文本。       | 按需激活 |
| `web.download` | 下载资源到本地文件，超限时拒绝写入不完整文件              | 为安装、素材获取、文档处理和离线分析提供文件入口，并通过大小限制避免损坏文件或耗尽磁盘。 | 按需激活 |

访问 localhost、私有 IP 或私有 DNS 目标时按明确请求直接执行。

### 系统控制

| 工具                 | 功能                                            | 为什么写入项目                                                                         | 默认暴露           |
| -------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------ |
| `system.time`        | 获取当前时间、日期、时区和时间戳                | 模型无法可靠记住实时时间；日程、日志、定时任务和“现在几点”等行为需要可信的本地时间源。 | 按需激活           |
| `system.media`       | 播放/暂停、上一首、下一首、停止、音量加减和静音 | 把高频系统行为做成原子动作，供媒体控制、会议和声音环境相关工作流直接组合。             | 按需激活           |
| `system.power`       | 锁屏、睡眠、重启和关机                          | 补齐设备级生命周期控制，使完整的语音操作覆盖到系统电源行为并直接执行。                 | 按需激活，直接执行 |
| `network.interfaces` | 枚举本机网络接口和地址                          | 为联网诊断、局域网任务、代理配置和失败排查提供基础状态，而不是让上层臆测网络环境。     | 按需激活           |

### 文件验证

| 工具        | 功能                           | 为什么写入项目                                                                                   | 默认暴露 |
| ----------- | ------------------------------ | ------------------------------------------------------------------------------------------------ | -------- |
| `fs.exists` | 检查路径是否存在及类型         | 作为最轻量的文件前置条件和结果验证工具，让工作流在执行覆盖、打开、删除和移动前先检查目标状态。   | 按需激活 |
| `fs.hash`   | 流式计算 SHA-256、SHA-1 或 MD5 | 用于下载完整性、缓存一致性和操作前后验证，使“文件已经处理完成”可以由数据证明，而不是依赖文件名。 | 按需激活 |

## 3. 工具面控制

新增工具不会全部暴露给实时语音模型。`ToolSurface` 仍限制最多 24 个可见工具，
新增的多数能力通过 `capability.search / describe / invoke` 按需发现。

这避免了：

- 工具 schema 占满模型上下文。
- 新工具挤掉 Steam、Office 等状态相关工具。
- 低频高风险工具持续出现在模型的默认选择中。

## 4. 复杂任务示例

```text
任务：把当前网页里的错误信息整理并保存到桌面

1. ui.inspect
2. screen.capture
3. screen.ocr
4. fs.create_file
5. condition.check(path_exists)
6. fs.hash
```

```text
任务：安装一个本地工具并确认安装结果

1. web.download
2. fs.hash
3. process.run
4. condition.wait(path_exists)
5. condition.check(path_is_file)
```

```text
任务：关闭一个卡死的应用

1. process.list
2. process.inspect
3. process.stop（确认）
4. condition.wait(process_missing)
```

## 5. 安全约束

- `process.run/start/stop` 按明确用户指令直接执行。
- `system.power` 按明确用户指令直接执行。
- 私有网络访问按明确用户指令执行。
- 覆盖已有下载文件时直接执行并保留既有备份策略。
- `ui.action` 使用绝对坐标，调用方应先通过 `ui.inspect` 获取控件位置。
- UI 输入、截图和 OCR 只在本机处理。
- 工具参数和权限仍由 `ToolRegistry` 统一准备和检查。
